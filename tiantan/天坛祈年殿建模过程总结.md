## 0. 一句话概括

**不是"在视口里一块块摆模型"，而是"把建筑翻译成一组几何规则和参数表，再写脚本一次性生成"。**

## 2. 是否有"先设计"？—— 有，而且是最关键的一步

**设计发生在写第一行建模代码之前，但设计的形式不是画草图，而是三段文字层面的推演。**

### 2.1 关键洞察：这是圆形建筑

天坛祈年殿的平面是圆的，整栋建筑**绕竖直轴旋转对称**。这一条直接决定了整个技术路线：

> 任何"横截面绕 Z 轴旋转一圈"的部件，都可以用一个函数生成 —— 也就是**旋转体（lathe / revolve）**。

一旦意识到这点，建筑就"降维"了：原本要处理三维形体，现在只需要在 **（半径 r, 高度 z）二维平面**上画一条剖面线，剩下的交给旋转。

例如：

| 部件 | 二维剖面 | 旋转后得到 |
|---|---|---|
| 三层台基 | 阶梯状折线 | 三层圆形石台 |
| 殿身墙 | 竖直线 + 顶部收口 | 圆柱形墙体 |
| 屋顶 | 上凹的曲线 + 回程曲线 | 中空锥壳（有厚度的屋瓦面） |
| 额枋 / 腰线 / 栏板 | 细长矩形 | 圆环带 |
| 宝顶宝珠 | 半圆弧 | 球体 |

### 2.2 几何分解：把描述拆成 8 个子系统

用户给的需求是一段自然语言描述，我把它逐句拆成**可独立建模的部件**：

> "三重蓝色琉璃瓦圆形攒尖顶，屋顶中央有金色宝顶，三层汉白玉雕花石基座和栏杆，红色漆木立柱，精美的斗拱结构"

拆解结果：

```
1. 台基系统     —— 三层汉白玉圆台 + 束腰雕花 + 压边
2. 栏杆系统     —— 每层台基边缘的望柱 + 环形栏板（南侧留口）
3. 踏道系统     —— 南侧三层台阶 + 中央丹陛石
4. 柱网系统     —— 三层各 12 根红柱 + 石鼓柱础 + 柱顶额枋环
5. 殿身系统     —— 底层隔扇门窗带 / 中上层收进的墙体
6. 斗拱系统     —— 每层柱顶 24 组"坐斗-拱-升"单元 + 挑檐檩
7. 屋顶系统     —— 三层锥壳 + 瓦垄 + 垂脊 + 檐口瓦当 + 檐下椽
8. 宝顶系统     —— 须弥座 + 莲瓣 + 承露盘 + 金宝珠 + 尖顶
```

每个子系统都能**单独调试、单独替换参数**，不会牵一发动全身。

### 2.3 建模原语选型：只造 4 把"工具"

拆解完部件后，发现所有部件都能落到 4 种基本形体上，于是不去逐个写建模代码，而是**先把这 4 个原语写成通用函数**：

| 原语 | 用途 | 覆盖的部件 |
|---|---|---|
| `lathe(name, profile, segments)` | 旋转体，最核心 | 台基、墙体、屋顶壳、环带、宝顶、球体 |
| `poly_prism(sides, radius, height, taper)` | 多棱柱/圆台 | 柱子、望柱 |
| `merged_cubes(matrices)` | 大量小方块合并成**单个**网格 | 斗拱、雕花、瓦当、椽子、栏杆望柱 |
| `roof_ribs(azimuths, samples, ...)` | 沿曲面母线扫掠条带 | 瓦垄、垂脊 |

`merged_cubes` 这个设计很关键：斗拱有 72 个小方块、瓦当有 144 个、台基雕花每层上百个。如果每个方块建一个对象，场景会涨到几千个对象、操作卡顿；**合并成单个 mesh 后，158 个对象就装下了全部细节，面数还控制在 10 万级**。

### 2.4 尺寸怎么定？—— 参数表 + 几何约束推导

尺寸不是拍脑袋，分三种来源：

**（1）用真实建筑的比例做锚点。**
祈年殿实测：总高约 38 m，下檐檐口直径约 34 m，祈谷坛三层高约 6 m。按约 0.8 的比例缩放，得到模型基准：

```python
BASE = [(14.60, 0.00, 1.40),   # 一层台基 (外半径, 底 z, 顶 z)
        (13.10, 1.40, 2.80),   # 二层
        (11.60, 2.80, 4.20)]   # 三层（祈谷坛顶层）
COL_R_OUT, COL_R_MID, COL_R_IN = 8.60, 6.30, 4.05   # 三层柱圈半径
COL_D = 0.92                                         # 柱径
```

**（2）用几何约束反推，而不是猜数字。**
这是最容易被忽略、但最影响成品质感的部分。举三个真实用到的约束：

- *约束一：屋顶必须收在上一层柱圈**内侧**，否则柱子会穿出屋面。*
  所以每层檐的"收顶半径"必须 **小于** 上一层柱圈半径：
  `檐1 收顶 6.55 < 中柱圈 6.30`？ → 不成立，于是把中柱圈从 6.60 调到 6.30，满足 `6.55 > 6.30`（柱圈在内侧）。

- *约束二：每层"腰"（露出的红柱段）要有足够高度，否则看起来三层檐糊成一团。*
  柱子在半径 R 处，被下檐屋面遮挡到高度 H，则可见高度 = 柱顶标高 − H。
  于是把每层柱顶都排在"下层檐收顶 z + 约 2 m"的位置：

  ```
  檐1 收顶 17.65 → 中柱顶 19.75（可见 ~2.1 m）
  檐2 收顶 24.25 → 上柱顶 26.15（可见 ~1.9 m）
  ```

- *约束三：屋檐出挑要与柱高成比例。*
  檐口半径 − 柱圈半径 ＝ 出挑量，控制在 2 m 左右（柱高 8.6 m 的约 1/4），超过就会变成"大伞压小柱"。

**（3）其余装饰件用"每圈几个"的密度参数控制，而不是绝对坐标。**
例如瓦垄 72 条/圈、垂脊 12 道、斗拱 24 组、檐口瓦当 144 枚、栏杆望柱按周长 ÷ 3.15 m 自动算数量。这样改一次半径，装饰密度会自动跟着适配。

## 3. 第二步：搭工具库 `lib/blender_lib.py`（公共）

按上面的设计，先写"工具"再写"建筑"。核心是旋转体函数：

```python
def lathe(name, profile, segments=96, ...):
    """
    profile: [(radius, z), ...] 由下至上的剖面点
    逐环生成顶点 → 相邻环之间连四边形 → 首尾按需封口
    """
```

实现要点：

- **半径为 0 的点自动收成顶点**：`remove_doubles` 会把重合顶点焊接掉，于是"锥尖/球顶"不用特殊分支；
- **剖面首尾相接即可成闭合壳体**：把"外曲面 + 檐口 + 内曲面 + 回檐口"串成一条闭合折线，一次旋转就得到**有厚度的屋顶壳**（而不是一张单面纸片）；
- **法线统一重算**：`recalc_face_normals` 保证不出现黑面；
- **平滑标记**：曲面（屋面、宝顶、柱身）开 smooth，折面（台阶、方块）关，一次写好不用回头补。

其余工具：材质工厂、棱柱、圆环带（`ring_band` 用一条"矩形剖面"旋转出来）、四维变换矩阵助手 `mat_trs`、母线采样 `sample_curve`（带 `power` 参数，用来做中式屋顶的**举折凹曲线**）、曲面法向偏移 `curve_offset`、条带扫掠 `roof_ribs`。

## 4. 第三步：下半身（`tiantan/build_p1.py`）

先建"稳的、方的、能定位的"部分，因为它们提供**标高基准**（后面所有部件都引用 `PLATFORM_TOP`、柱顶标高等变量，而不是硬编码数字）。

顺序与理由：

1. **地面盘** —— 给场景一个视觉落脚点；
2. **三层台基** —— 每层用一条折线剖面旋转得到：竖直面 + 顶部收进 + 台面；再叠加三条装饰环带（束腰线、回纹浮雕带、台面压边），对应需求里的"**雕花**石基座"；
3. **栏杆** —— 沿每层台面边缘做环形薄壁当栏板，望柱则用 `merged_cubes` 一次性合并（每根望柱 = 柱身 + 柱头 + 柱顶凸头三块），并按角度跳过南侧一段形成**踏道开口**；
4. **踏道** —— 南侧（-Y）三层台阶 + 中央凸起的丹陛石；
5. **柱网** —— 三圈 12 根柱：外圈落地檐柱（带石鼓柱础），中圈、内圈金柱；每圈柱顶加一道红色额枋环。

执行结果：**517 个对象**（此时还没做屋顶）。这里对象数偏多主要是每根柱子、每根望柱各占一个对象，属于可接受的成本。

## 5. 第四步：上半身（`tiantan/build_p2.py`）

第二部分写在一个文件里，但它开头会**重新执行 part1**，保证任何一次运行都是从零到整的完整重建，不会出现"改了一半"的状态。

### 5.1 殿身

底层一圈红墙（半径比柱圈小 1.05 m，故意让 12 根柱子凸出来形成柱廊感），墙外贴两道隔扇门带（红门板 + 暗金横框），底部石质墙裙，柱与墙之间加一道坐凳楣子联系构件。

### 5.2 斗拱

每层柱顶到檐口之间那 0.7~0.9 m 是斗拱的舞台。做法是把这段高度按比例分成四层：

```
坐斗（0.56 大方块）→ 拱（0.36×1.45 横条，沿切向）→ 升（0.52 方块）→ 金线
```

每个柱位和每两个柱位的中点各放一组（共 24 组），用 `merged_cubes` 合并成两个对象（彩画件 + 金线件）。

### 5.3 屋顶（最重要的 30 行）

屋面的剖面是这样拼出来的：

```python
outer = [檐口翘边] + 24 点母线曲线 + [收顶缩口, 中轴顶点]
inner = [中轴内顶点] + 母线曲线整体下移 thickness（倒序）+ [檐口内侧]
profile = outer + inner        # 首尾相连 → 闭合 → 旋转成有厚度的锥壳
```

母线曲线用 `sample_curve(..., power)` 生成：`r(t) = r_top + (r_eave − r_top)·(1−t)^power`。
**`power` 就是中式屋顶的"举折"参数**——`power > 1` 时，檐口附近坡度平缓、靠近顶部陡峭，正好是中式屋顶那条著名的"上凹曲线"。三层分别取 1.45 / 1.50 / 1.62。

在锥壳之上再叠三样东西：

- **瓦垄**：72 条沿母线扫掠的连续凸条（`roof_ribs`），表现琉璃筒瓦；
- **垂脊**：12 道更粗的脊，`taper=0.62` 让它越往顶越细，符合攒尖顶的收束感；
- **檐口细节**：144 枚瓦当 + 96 根檐下椽 + 一圈绿色连檐板。

### 5.4 宝顶

按"须弥座 → 莲瓣圈 → 承露盘 → 金宝珠（半径 1.32 的球）→ 顶珠 → 尖 → 尖端小珠"自下而上串起来，高度约 5.9 m，全部用金属材质。

## 7. 第六步：8 轮迭代修正（最耗时的部分）

**每一次都是"渲染 → 看图 → 定位问题 → 改参数/改算法 → 再渲染"。** 记录如下：

| 轮次 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 渲染出来是全白/全灰，没有任何颜色 | ① 材质 `node_tree.nodes.get("Principled BSDF")` 在 Blender 5.2 返回 `None`，颜色根本没写进去；② 用的 `render_viewport_to_path` 其实是灰度视口渲染，还写到临时目录 | ① 改为按类型查找 `next(n for n in nodes if n.type == 'BSDF_PRINCIPLED')`；② 改用 `bpy.ops.render.render(write_still=True)` + `scene.render.filepath` |
| 2 | 屋顶像"三层飞碟"，柱身几乎看不见 | 檐口出挑过宽（10.85 vs 柱圈 8.0）、屋顶"举折"过平（power 2.05）、层高被压扁 | 重设 `EAVE` 表（檐口/收顶半径与标高）、power 降到 1.45、柱圈外移到 8.60、台基加高 |
| 3 | 瓦面像一排排小珠子，不是连续的瓦垄 | 用"沿母线的离散小方块"拼瓦垄，方块之间有间隙且旋转角逐段跳变 | 新增 `roof_ribs` + `curve_offset`：沿曲面**扫掠**连续条带，一次生成一整条 |
| 4 | 中/上层柱子像从瓦面里"长出来"（穿模） | 檐的收顶半径与上一层柱圈半径几乎相等甚至更小 | 按"收顶半径 > 柱圈半径"的约束把中/内柱圈内收到 6.30 / 4.05 |
| 5 | 台基像一圈薄盘子、栏杆密得像针筒 | 台基每层仅 0.95 m 高；栏杆按 1.55 m 间距排 | 台基加高到 1.4×3；栏杆间距逐步调到 3.15 m，望柱加粗到 0.34 |
| 6 | 材质像塑料、装饰金线太抢眼 | 红漆 roughness 0.28 + coat 0.35 反光过强；门框用了亮金 | 红漆 roughness 提到 0.46、coat 降到 0.12；门框/腰线改用暗金材质，金线从 3 条减到 2 条 |
| 7 | 构图裁切（宝顶和台基出画） | 相机距离与目标点高度不匹配 | 相机外移到 (36,-53,26)、目标抬到 z=17.5、焦距 48 mm |
| 8 | 瓦垄太密发糊 / 太疏露白 | 瓦垄数量与宽度不匹配 | 最终定在 72 条、半宽 0.128、高 0.052，密度与反光取得平衡 |

**这套"渲染—看图—改参"的闭环，是本次复杂建模能收敛的唯一原因。** 没有哪一次是"想清楚了再一次写对"的。

## 9. 复盘：复杂建模为什么能做成

### 9.1 六个关键方法

1. **先找对称性，再动手。** "圆形建筑 → 全部是旋转体"这一个判断，把三维建模问题降成了二维剖面问题，工作量减少一个数量级。
2. **先造工具，再造零件。** 4 个原语函数覆盖了 30+ 种部件；后续所有"加个细节"都只是多调一次函数。
3. **一切参数化，一切可重跑。** 全部尺寸写在文件顶部的参数表里，脚本每次从 `clear_scene()` 开始跑完整流程，模型永远可复现、可微调。
4. **用几何约束代替审美猜测。** "收顶半径 > 柱圈半径""腰高 ≥ 2 m""出挑 ≈ 柱高/4"这些是可以计算、可以验证的，比反复目测快得多。
5. **密集小构件必须合并网格。** 斗拱、瓦当、雕花、望柱全部合并，否则几千个对象会让 Blender 和脚本都难以操作。
6. **闭环验证。** 每次改动都渲染、看图、再改。渲染是唯一的验收标准。

### 9.2 "我是怎么知道每一部分该怎么建的？"

这个问题可以拆成四个来源：

- **来源一：需求文本 → 几何体。** 用户说"三重蓝色琉璃瓦圆形攒尖顶"，我读到的信息是：三个同轴回转锥壳、颜色深蓝、材质有釉面（低粗糙度 + 清漆层）、顶部收尖。自然语言里的每个形容词都能映射成一个几何或材质参数。
- **来源二：真实建筑的比例数据。** 尺寸不是随便定的，是用祈年殿的实测比例（高 38 m、檐径 34 m、台基 3 层）缩放后作为基准，再按约束微调。
- **来源三：几何约束计算。** 柱子会不会穿出屋面、每层腰能露出多少、出檐是否过分——这些在建模前就能用算术推出来，属于"可以算准"的部分。
- **来源四：视觉反馈迭代。** 比例是否协调、颜色是否沉稳、细节密度是否合适，这些只能靠渲染出来看，然后一轮轮逼近。

前三个来源负责"结构正确"，第四个来源负责"看起来对"。两者缺一不可。

### 9.3 关于"是否先设计场景"

**是，但设计的形式是"参数表 + 几何分解 + 约束推导"，而不是先画草图或在 3D 视口里做布局。**
真正写代码之前，已经确定了：建筑拆成哪 8 个子系统、每个子系统用哪个原语、每个部件的标高和半径、部件之间的相互约束。代码只是这份设计的翻译。

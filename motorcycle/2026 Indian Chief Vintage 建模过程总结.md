> 记录时间：2026-09-29
> 环境：Blender 5.2.2 LTS（Python 3.13.13）+ Blender MCP（`execute_blender_code`）
> 产出目录：`motorcycle/`，公共库：`lib/`

## 0. 一句话概括

**不是"照着照片捏一辆车"，而是"把一辆车拆成十条尺寸自洽链，用参数化曲面逐件生成，再用穿插检测验收"。**

整车拆成 10 个部件子系统，由 1267 行 Python（8 个脚本）生成 184 个独立命名对象、4.6 万顶点 / 8.9 万三角面。轴距与座高与官方规格**完全吻合**，总长/总宽/总高偏差均在 0.81% 以内。

与天坛最大的不同：天坛的难点是"形体"，摩托车的难点是**"让位"**——每个部件都要为别的部件腾出空间，而这些空间关系可以在建模前算清楚。

## 2. 第二步：先把"真车"查清楚（天坛没有这一步）

天坛是古建筑，尺寸可以按"实测比例缩放"来估。**摩托车不行——它有成百上千个可查的硬数字，猜一个就是错一个。**

### 2.1 车型确认

任务是"2026 Indian Chief Vintage Sturgis, SD Edition"。先确认这不是虚构车型：

- Indian Motorcycle 于 **2026 年 1 月**发布 2026 款 Chief Vintage（品牌 125 周年首发车型）
- **2026 年 8 月**在第 86 届 Sturgis 摩托车集会上推出 **Sturgis, SD Edition** 限量版，**125 台逐台编号**
- 专属特征：Indian Motorcycle Red + Cream **双色涂装**、**多色印第安人头饰**油箱徽标、侧板**手绘 "56"**（致敬早期车手的参赛号）

### 2.3 从照片读出什么

下载了 10 张官方实车照片（Visordown 棚拍 + Maxim 发布会图）存于 `refs/`。关键的不是"看个大概"，而是读出**可量化的造型规则**：

| 观察到 | 转化为几何规则 |
|---|---|
| 前挡泥板包覆前轮远超半圈 | 包角取 200°，起始角 -24° |
| 裙边两侧下垂，边缘低于轮轴 | 裙边下垂量 sag = 0.062（前）/ 0.082（后），下垂集中在边缘（`skirt_pow = 2.35`） |
| 挡泥板中央有奶油色宽带、两侧是红裙边 | 沿横向参数 v 做**面级材质分配**，中央 58~62% 为奶油色 |
| 后挡泥板尾部向后突出成鸭嘴 | 尾部半径外扩 `tail_extend = 0.145` |
| 油箱下部奶油色、上部红色，侧面有头饰徽标 | 复合判据：高度分数 < 0.50 **且** 处于侧面（\|y\| > 0.46·半宽）才涂奶油色 |
| 缸头是银色横向鳍片、缸体是黑色 | 缸体/缸头用"鳍片筒体"，两种材质分色 |

### 2.4 参考资料的归档原则

`refs/` 下同时保存了照片、抓取的页面快照（`maxim.html`）和 `ReferenceData.md`（尺寸表 + 观察结论 + 照片来源 URL）。

归档原则：**凡是从外部取回的资料都算输入，一律纳入版本库**（链接会失效、页面会改版，丢了无法从代码重建）；只有**代码运行生成的图**才忽略。据此 `render/` 下 33 张 PNG（61.6 MB）被忽略，而 5.8 MB 的参考照片全部保留——它们的体积是代码的 70 倍，但不可再生。

## 3. 第三步：设计——与天坛完全不同的降维思路

### 3.1 关键洞察：没有全局对称，就"逐件降维"

天坛的降维是"整栋建筑绕 Z 轴旋转对称 → 三维降到二维剖面"。

**摩托车没有全局对称性**——但它也不是一盘散沙。每一类部件都能找到属于自己的"降维方式"：

| 部件族 | 降维方式 | 降成什么 |
|---|---|---|
| 轮胎、轮辋、大灯、皮带轮 | 绕自身轴回转 | 二维剖面（半径, 轴向）+ 角度范围 |
| 挡泥板 | 绕轮轴**部分**回转 + 横向裙边曲线 | (角度 u, 横向 v) 的双参数曲面 |
| 油箱、座椅 | 沿 X 轴放样的**一叠截面** | 每个截面是一条超椭圆曲线 |
| 车架管、车把、排气、脚踏杆 | 一条路径 + 一个圆截面 | 空间折线 + 半径 |
| 发动机缸体 / 缸头 | 轴向剖面 + 周期性鳍片 | 一条锯齿状剖面线 |

所以摩托车的技术路线不是"一个函数打天下"，而是**先判断每个部件属于哪一族，再调对应的原语**。

### 3.2 尺寸自洽链：摩托车真正的难点

这是本次最关键的认识。

天坛是**层层往上叠**：台基 → 柱网 → 斗拱 → 屋顶，只有一个方向，标高可以顺序推导。

摩托车是**各部件围绕同一坐标系互相让位**。至少存在四条必须同时满足的链条：

**链 A：车轮链（最简单）**
```
轮胎规格 → 轮半径 → 地面高度 → 前后轴心坐标（-1.626, 0, -0.003）
```

**链 B：前部链（转向几何）**
```
rake 29° → 前叉轴线方向 (sin29°, 0, cos29°)
       → 轴线参数化 on_axis(t)：任意 t 处得三角台 / 转向头 / 大灯安装点
       → 前叉顶端 z = -0.003 + 0.742·cos29° = 0.644 → 离地 0.967 m
       → 反推验证：加升高码 + 车把 + 后视镜 ≈ 总高 1232 mm ✓
```

**链 C：中部链（最容易翻车的一条）**
```
座高 686 mm → 座面 z = 0.3628
            → 座垫厚 70 mm → 座垫底 z ≈ 0.293
            → 车架上管在座椅下方必须低于 0.293，否则座椅插进管子里
            → 上管在 x = -0.40 处取 z = 0.262
            → 油箱底部必须高于上管顶部（0.2785），故油箱底部中央设 56 mm 隧道
            → 油箱顶部 z = 0.608
            → 缸头顶 z = 0.299（曲轴中心 + 0.329·cos24.5°），必须低于油箱底部 ✓
```

**第一版就是在这条链上翻的车**：油箱底部按"泪滴形"想当然设成 0.336，而上管顶部在 0.547——油箱把整根管子包了进去，渲染出来像"橄榄球骑在棍子上"。

**链 D：横向让位链**
```
前叉中心距（202 mm）→ 内间距 = 202 − 2×23 = 156 mm
                   → 前挡泥板宽度必须 ≤ 156，故取 146
                   → 但轮胎宽 130，挡泥板还要包住它 ✓
```

这条链第一版也错了：挡泥板取 166 mm，直接插进前叉管，实测穿透 −228 mm。

**结论：把这几条链在纸上（参数表里）算通，比在视口里调十次都快。**

### 3.3 部件分解：10 个子系统

```
1.  车轮系统      —— 轮胎断面 / 轮辋 / 轮毂 / 40 根交叉编织辐条 / 298 mm 制动盘
2.  前叉转向      —— 内外管 / 护罩 / 上下三角台 / 转向头管 / 顶盖
3.  车架系统      —— 上管 / 下管 / 摇篮 / 座管 / 枢轴横管 / 座椅横梁
4.  后摇臂悬挂    —— 摇臂 / 枢轴 / 后轴 / 双避震（含弹簧）
5.  发动机        —— 曲轴箱 / 变速箱 / 49° V 双缸（鳍片缸体 + 银色缸头）
                     / 缸头盖 / 推杆管 / 火花塞 / 空滤盖 / 正时盖 / 徽章
6.  车身覆盖件    —— 油箱 / 前后裙式挡泥板 / 悬浮单人座 / 侧板
7.  控制件        —— 宽幅上掠车把 / 升高码 / 握把 / 操纵杆 / 后视镜 / 脚踏板
8.  灯具          —— 大灯总成（壳+碗+玻璃+头饰）/ 前后转向灯 / 尾灯 / 牌照灯
9.  排气          —— 右侧双出直管 / 消声器尾段 / 排气口法兰
10. 传动          —— 皮带终传（前后皮带轮 + 外公切线皮带 + 连接筒）
```

### 3.4 建模原语选型：7 类工具

天坛只需 4 把工具，摩托车需要 7 类——但每一类都对应上面 3.1 节的一种降维方式：

| 原语 | 覆盖部件 | 关键实现点 |
|---|---|---|
| `grid_surface(fn, nu, nv)` | 挡泥板、裙边曲面 | 直接给 (u,v)→(x,y,z) 映射，裙边下垂写进 `r(u,v)` |
| `loft_rings(rings)` | 油箱、座椅 | 一叠等长顶点环连四边形；油箱的"隧道"写在截面生成里 |
| `sweep / pipe(path, section)` | 车架管、车把、排气、脚踏杆 | **平行传输标架**避免扫掠扭转；路径先过 Catmull-Rom 平滑 |
| `revolve(profile, axis)` | 轮胎、轮辋、大灯、皮带轮 | 支持 X/Y/Z 三轴；剖面自动闭合 |
| `finned_tube(...)` | 发动机缸体、缸头 | **一次旋转生成整摞散热鳍片**，剖面在 r_core / r_fin 之间锯齿交替 |
| `spoke_set(...)` | 每轮 40 根辐条 | 全部合并进**单个** bmesh，否则对象数爆炸 |
| `belt_loop(...)` | 皮带终传 | 外公切线 + 两端圆弧，用向量法求切点避免三角函数陷阱 |

其中 `finned_tube` 是这次最划算的设计：一个函数解决了 Thunderstroke 发动机缸体 + 缸头共约 30 片散热鳍片，改一个参数就能调整鳍片密度。

## 4. 第四步：参数表与公共库

分两层，与天坛同样的思路，但拆得更细：

**`motorcycle/moto_params.py`（车型专属，全部尺寸的唯一来源）**

```python
# 坐标系：后轮轴心为原点，-X 指向车头，+Z 向上，单位米
WHEELBASE = 1.626                 # 轴距（官方）
RAKE_DEG  = 29.0                  # 前倾角（官方）
SEAT_H    = 0.686                 # 座高（官方）
R_TIRE_F  = 0.2032 + 0.130*0.90   # 由轮胎规格反算
AXLE_F    = (-WHEELBASE, 0.0, GROUND + R_TIRE_F)
AXIS_DIR  = (math.sin(RAKE), 0.0, math.cos(RAKE))   # 前叉轴线方向

def on_axis(t, off_y=0.0):
    """前叉轴线上距轴心轴向 t 处的世界坐标"""
```

`on_axis()` 这个小小的参数化函数非常关键：三角台、转向头、护罩、大灯、转向灯的位置全部由它推导，**改一次 rake 角，整个前部自动跟着变**。

**`lib/mesh_tools.py` + `lib/scene_tools.py`（公共库，与车型无关）**

`mesh_tools.py` 收录了第 3.4 节的 7 类原语，外加：材质工厂（按节点 `type` 查找，规避 Blender 5.x 节点改名）、紧固件、数学辅助（Catmull-Rom、超椭圆、插值表）。
`scene_tools.py` 收录：渲染配置与 `render_still`、看板相机、三点布光、批量视图、网格统计与包围盒。

**这两个库不含任何摩托车专属概念**，后续做别的车（或任何机械件）可以直接复用。

## 5. 第五步：阶段 1 —— 整车比例骨架（`build_p1_blockout.py`）

顺序与理由：先立"骨架"和"最大体量件"，因为它们决定整车轮廓。

1. **车轮** —— 轮胎（断面绕轴旋转）/ 轮辋 / 轮毂 / 制动盘，先把四个基准坐标钉死；
2. **前叉与三角台** —— 全部走 `on_axis(t)`，管径 46 mm 按官方；
3. **车架** —— 上管 / 下管 / 摇篮 / 座管 / 枢轴管，管径 33 mm。**上管的路径是链 C 的载体**，必须与油箱底部、座椅底部同时相容；
4. **后摇臂 + 双避震**；
5. **油箱** —— 沿 X 放样 41 个超椭圆截面，底部中央挖 56 mm 隧道骑在上管上；
6. **前后挡泥板** —— 裙式曲面，包角 200° / 168°，带裙边下垂与尾部鸭嘴；
7. **座椅** —— 马鞍形放样，前端窄而下探、中部微凹、后端上翘；
8. **侧板** —— 座椅下方三角盖板；
9. **发动机占位体** —— 先只保证"尺寸正确"，不追细节。

执行结果：73 个对象。**此时整车轮廓已经能一眼认出是 Chief** —— 这一步的价值就在于"用最小成本验证比例"。

## 6. 第六步：阶段 2 —— 机械部件（`build_p2_engine_wheels.py`）

这一阶段补的是"体积感"和"机械可信度"：

- **辐条**：每轮 40 根，交叉编织 2 跨。全部合并成单个网格（`spoke_set`），否则光辐条就要 80 个对象；
- **发动机细化**：把占位圆柱换成 `finned_tube` 鳍片筒体（缸体 r_fin 0.0745 / 缸头 r_fin 0.0895 用 Turbo Silver）；补变速箱壳体把曲轴箱与摇臂枢轴之间的空隙填上（**第一版这里太空，车看起来"骨架感"很重**）；加推杆管、火花塞、缸头盖压紧螺栓；
- **曲轴箱右盖**：黑色圆盘 + 古铜色印第安人头徽章 + 黑色环；
- **空滤盖**：116 立方英寸大圆盖 + 镀铬装饰环 + 中心盘；
- **制动卡钳**：按极坐标定位在制动盘外缘（前 128°、后 -152°），并让盒体沿径向取向；
- **皮带终传**：前皮带轮（变速箱输出）+ 后皮带轮 + 外公切线皮带 + 连接筒。

## 7. 第七步：阶段 3 —— 控制件与灯具（`build_p3_controls.py`）

- **排气**：右侧双出。前缸管最终落到下位、后缸管落到上位，两根平行后延，末端加粗成消声器尾段，入口端加法兰；
- **大灯总成**：整流壳（前大后小的回转体）+ 灯圈 + 反射碗 + 灯泡 + 微凸玻璃 + 顶部头饰装饰 + 左右支架；
- **转向灯**：前灯装在前叉两侧，后灯装在后挡泥板后部两侧（橙色透镜用发光材质）；
- **尾灯**：后挡泥板末端，红色发光；
- **车把**：走 `right_path` 六点折线，经 Catmull-Rom 平滑后扫掠成管，左右镜像；配升高码、握把（橡胶）、操纵杆、开关组；
- **后视镜**：镜杆 + 镜壳 + 镜面，位置同时受"握把位置"和"总高 1232 mm"两个约束；
- **脚踏板**：全长橡胶板 + 支架 + 换挡/制动杆 + 橡胶踏杆。

## 8. 第八步：阶段 4 —— 涂装与徽标（`build_p4_paint.py`）

Sturgis SD Edition 的辨识度全在这一层，做法是**面级材质分配 + 几何贴片**：

| 目标 | 实现 |
|---|---|
| 挡泥板中央奶油带 + 红色裙边 | 按 `grid_surface` 的横向面索引 `k % nv` 反推参数 v，\|v−0.5\| < 0.29 分配奶油槽，其余红槽 |
| 油箱下侧奶油色、上部红色 | 逐面求中心点 → 反算该处油箱上下边界 → 高度分数 < 0.50 且处于侧面（\|y\| > 0.46·半宽）才给奶油色 |
| 多色头饰徽标 | 棕色椭球当面部 + 9 根米色羽毛呈 18°~162° 扇形辐射 + 黑色羽尖 + 黑色底座弧 |
| 油箱 "Indian" 手写体 | 文字曲线对象（FONT），加载 `BRUSHSCI.TTF` 手写字体，挤出 1.6 mm |
| 侧板 "56" | 同上，字号 62 mm，黑色 |

**为"可编辑"留的后路**：全部走材质槽 + 面索引，不烘焙贴图；文字保持曲线对象，随时可改内容与字号。

## 9. 第九步：技术检查 —— 部件穿插检测（天坛没有的一步）

天坛是单体建筑，一根柱子穿出屋面肉眼就能发现。**摩托车的部件互相嵌套（挡泥板包轮、油箱跨车架、皮带绕摇臂），肉眼在 3/4 视图里很难判断哪里差了 2 mm。**

于是写了一个基于最近点查询的检测器（`moto_common.check_penetration`）：

```python
for p in A 的采样顶点:
    pl = B.matrix_world.inverted() @ p
    ok, loc, nrm, _ = B.closest_point_on_mesh(pl)
    sd = (pl - loc).length * (1 if (pl-loc).dot(nrm) >= 0 else -1)
```

对 17 组"本应分离"的部件对逐一检查，输出最小距离与穿透点数：

```
Wheel_Front_Tire | Fender_Front     : -1.7 mm   ← 报警
Fork_Lower_L     | Fender_Front     : -228.0 mm ← 严重
Drive_Belt       | Swingarm_L       : -4.9 mm   ← 报警
Seat_Solo        | Frame_Backbone   : -6.8 mm   ← 报警
```

**这套检测是"返工"的转折点**：前叉切入挡泥板 −228 mm 是肉眼在侧视图里看不出来的（两件都是黑色），检测一跑就暴露了。

局限也要说明：`closest_point_on_mesh` 对**单面曲面**（挡泥板带 solidify 修改器，原始网格是单层）的法线方向判断不可靠，会把"在背面"误报成"在内部"。所以解读时看**距离的绝对值**，`inside_pts` 只作参考——绝对距离超过 70 mm 的负值基本都是误报。

## 11. 复盘

### 11.1 六个关键方法

1. **先查真车，再动手。** 摩托车有大量可查硬数字，猜一个错一个。官方规格表让 5 项验收指标里有 2 项（轴距、座高）能做到零误差。
2. **逐件降维，而不是找全局对称。** 整车无对称性，但每个部件都能降到"二维剖面 + 一条路径"。判断部件属于哪一族，比设计一个万能函数更省事。
3. **把尺寸自洽链在参数表里算通。** 链 C（座面→上管→油箱）和链 D（前叉间距→挡泥板宽度）是本次翻车最惨的两处，也都是"事前算一下就没事"的问题。
4. **先造工具、再造零件；先立骨架、再补细节。** 阶段 1 结束时整车已可辨认，后面三个阶段都是在骨架上"加肉"。
5. **密集小构件必须合并网格。** 80 根辐条、30 片散热鳍片如果各自成对象，场景立刻失控。合并后 184 个对象装下全部细节。
6. **用检测代替目测。** 部件互相嵌套时，−228 mm 的穿插在黑色零件之间肉眼不可见。把"最小距离"变成数字，才知道该改哪里、改多少。

### 11.2 "我是怎么知道每一部分该怎么建的？"

四个来源，与天坛一致，但权重不同：

- **来源一：官方规格 → 硬约束。** 轴距、座高、轮径、前倾角、缸径行程——这些是不可协商的，必须精确落位。
- **来源二：实车照片 → 造型规则。** 照片不提供数字，但提供"包角多少、裙边垂到哪、颜色怎么分"这类规则。关键动作是把形容词翻译成参数（"裙式挡泥板" → 包角 200° + 裙边下垂 62 mm + `skirt_pow` 2.35）。
- **来源三：几何推导 → 部件定位。** `on_axis(t)`、油箱底部跟随上管坡度、挡泥板宽度容于前叉内间距——这些都能算，算准了就不用试。
- **来源四：渲染反馈 → 审美与体量。** 座椅厚薄、侧板位置、辐条明暗、空滤盖远近，只能看了才知道。

**前三个来源负责"尺寸对、不打架"，第四个来源负责"看起来像"。** 摩托车的比例是硬约束，所以来源一~三的占比明显高于天坛。

### 11.3 与天坛的对比

| 维度 | 天坛祈年殿 | 2026 Chief Vintage |
|---|---|---|
| 降维方式 | 全局旋转对称 → 二维剖面 | 逐件降维（回转/放样/扫掠/鳍片） |
| 尺寸来源 | 实测比例缩放 + 约束推导 | 官方规格硬锚点 + 照片造型规则 |
| 主要难点 | 形体（屋顶举折曲线） | **让位**（部件空间关系） |
| 迭代重点 | 比例协调、细节密度 | 穿插修正、体量感 |
| 特别的一步 | 屋顶闭合剖面一次旋转成壳 | **部件穿插自动检测** |
| 验收方式 | 4 视图目视 | 尺寸对比 + 17 组间隙检测 + 多视图目视 |

### 12.3 复现方式

在 Blender MCP 的 `execute_blender_code` 中执行：

```python
import sys, os
ROOT = r'd:/work/AI/BlenderMCPTest/try1'

        sys.path.insert(0, p)
```

- 整车比例 / 车架走向 / 油箱曲面 → `moto_params.py` 的 `WHEELBASE`、`RAKE_DEG`、`TOP_TUBE`、`TANK_*`
- 挡泥板形状 → `moto_params.py` 的 `FENDER_*`（包角、间隙、裙边下垂、尾扩）
- 发动机尺寸 → `moto_params.py` 的 `CYL_*`、`HEAD_*`、`V_ANGLE`
- 涂装分色比例 → `build_p4_paint.py` 的 `center_ratio`（挡泥板）与高度分数阈值（油箱）
